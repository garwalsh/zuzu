Part 1

The problem

Why this is worth building

A USCIS form is a literacy test with a filing fee.

  1. 1.a.

    They are long, in English, and legally precise. One wrong box costs months — a rejected filing is not a retry, and a status can lapse while you wait for the letter.

  2. 1.b.

    They are hardest for exactly the people the system already fails: disabled, elderly, low-literacy, and non-English-speaking applicants.

  3. 1.c.

    The alternative is a lawyer at roughly $2,000, or filing alone and hoping.

What one answer costs

Naturalisation, Form N-400, has 273 fields. The first one wants your alien registration number. This is where it has to go on the page:

form1[0].#subform[0].#area[0].Line1_AlienNumber[0]

That is the real field name, extracted from the real PDF. Guess it wrong and the answer is accepted, saved, and silently absent from the printed form.

The information is not the hard part. Every applicant knows their own date of birth. The form is the hard part.

Part 2

The approach

Turn the form into a conversation

The voice agent knows nothing about any specific form. It asks whatever the orchestrator hands it.

  1. 01

    Listen. ElevenLabs handles speech, language detection and turn-taking, in the caller's own language.

  2. 02

    Identify. “My work permit” — never “I-765”. Plain words or a pasted URL resolve to the right form.

  3. 03

    Ask. One question at a time, read back for confirmation before it is kept.

  4. 04

    Fill. The official AcroForm PDF, by field name, validated against the real document.

  5. 05

    Hand over. The completed form plus the exact list of documents to attach.

One decision-maker

Every judgement lives in the orchestrator. The voice loop is deliberately thin, so changing how the interview works never means editing a prompt in a vendor's console.

Answer stored in 0.4 ms
Model on that path None

A human is mid-sentence while save_field and get_missing_fields run, so nothing slow is allowed on that path — no model call, no filesystem, no PDF work.

Render is the deployment, and the seam

One render.yaml stands the whole thing up. ElevenLabs reaches the orchestrator by public HTTPS at its Render URL — that is the only address the voice agent knows, and every server tool it has points at it.

The rule that does not bend

The model decides what to do: who acts next, what to say, when the work is finished. Code decides what is true: every field value, every validation outcome, every byte written to the page.

A hallucinated hand-off wastes a round trip. A hallucinated date of birth is a rejection months later, and the applicant pays for it.

The agentic side — Band

Six agents, talking to each other

Each agent holds its own WebSocket to Band under its own per-agent key, and addresses the others by mention.

Owns the conversationIntake What to ask next, and when the interview is finished. next_question · session_state · recall_profile
Owns provenanceExtractor Where each value came from: voice, memory, or a document. collected_values · recall_profile · remember_fact
Owns placementMapper Which box on which form each answer belongs in. map_values · session_state
Owns the checksValidator The mistakes only visible across several answers at once. cross_check · collected_values
Owns the documentFiller Writes the PDF, or refuses and says which answer blocked it. write_form · cross_check
Owns the recordAuditor Seals what everyone did, and closes the caller's memory. seal_record · record_episode · learn_rule
Auditoropens the room ▸ Intake▸ Extractor▸ Mapper▸ Validator▸ Filler▸ Auditor seals

They decide, not a loop

Each agent reasons with MiniMax-M3 through TokenRouter, and is handed Band's own tool schemas — so it sends a message, lists the participants, or pulls somebody in using Band's vocabulary, not ours.

The whitelist is the boundary

An agent cannot write a PDF because write_form is not in its list — not because its prompt asked it nicely. Five of the six physically cannot produce a filing.

Two independent records

/audit is Zuzu's account, durable in Postgres. /room reads the same conversation back out of Band's own API — so “they really did talk over Band” is checkable without trusting this service.

Every turn records the tools it ran, who it addressed, why, and which of three decided it: the model, the deterministic fallback, or an answer that came back unusable. Without TOKENROUTER_API_KEY the fleet still runs — on the fixed order above. The orchestration loses its judgement; nobody loses their filing.

Part 5

The memory side

Three tiers, in Postgres

A flat store is the wrong shape. Three kinds of knowledge, three lifetimes, three ways to forget.

Semantic

Facts that outlive the call.

country of citizenshipMexico
date of birth1998-04-12

Prefills the next form, whichever form that turns out to be.

Episodic

Calls that happened.

I-765 · 2026-07-2832 answers, completed

Lets Zuzu say “last time we filed your renewal” instead of greeting a returning applicant as a stranger.

Procedural

Rules learned about this person.

applicantspeaks Spanish
applicantno SSN — do not lead with it

Learned once, applied on every later call.

Written by the agents, not just by endpoints

The Extractor decides which answers are worth keeping. The Auditor records the episode and learns the rules. They call remember_fact, record_episode and learn_rule as tools, mid-conversation — the tiers are a product of the agents doing their jobs.

Whose memory it is, provably

Every row is scoped by SHA-256(tenant ␟ caller). The same person at two clinics is two files; the store never holds a raw phone number; and a caller with no id gets no memory in either direction, because every anonymous caller would otherwise hash to one shared key.

Identifiers — SSN, A-number, passport — are not persisted at all unless the organisation has explicitly opted in. Row-level security denies everything but the service key.

A form is data, not code

Twelve forms, none hand-written

Adding a form is one request. Nothing in api/ names a specific form.

Zuzu fetches the fillable PDF, extracts its AcroForm inventory, and derives the questions from the document's own screen-reader tooltips. No deploy, no code change.

Field names are extracted, never recalled by a model. A hallucinated field name is an application that silently loses half your answers — so the model only writes the wording, and every reference is validated back against the real document.

What the real document taught us

We built against the actual USCIS PDF, edition 08/21/25. It disagreed with our own spec four times.

Our spec saidThe document said
Initial / Renewal / Replacement Initial / Replacement / Renewal Taking the spec literally checks “replacement” for every renewal applicant — the most common category.
Collect parents' names and the SSA-card request Neither exists on this edition Three questions we would have asked with nowhere to put the answers.
Fill the AcroForm fields Hybrid AcroForm + XFA, AES-encrypted Fill it naively and the applicant opens a blank form.

The stack

What each one actually does
ToolJob it does here
ElevenLabsThe entire interface. Five server tools — identify_form, set_form, get_missing_fields, save_field, generate_form — pointed at the Render URL. session_id is bound to system__conversation_id, so the id the dashboard watches and the id the agent sends are the same by construction rather than by convention.
BandThe agents' actual transport. Rooms, participants, mentions, and a message log we can read back. Free tier: the Agent API works; the Human API answers 403 plan_required.
TokenRouterMiniMax-M3, reached OpenAI-style, so Band's tool schemas pass straight through. Agent reasoning, plus spoken-value normalisation — “nineteen ninety-eight, April twelfth” → 1998-04-12.
SupabaseSemantic, episodic and procedural memory in Postgres, keyed by a hash of tenant and caller. RLS denies everything but the service key.
rtrvr.aiReads uscis.gov, which returns 403 to scripted requests — it fingerprints the TLS handshake, so headers do not help. 17 live document requirements, narrowed per applicant.
RocketRidePipeline-as-JSON for form intake and model selection. The model is chosen in that JSON, not in Python.
RenderOne blueprint deploys the service, and its public URL is the address every ElevenLabs tool call is sent to.

How we know it works

And what we are not claiming
Tests203
Prod checks63/63

We attacked it, then fixed what landed

A 42-agent adversarial audit ran against the repo with one instruction: find claims the code does not support, then try to refute each finding before reporting it. 28 survived. All are fixed, each with a test that fails if it returns.

  • ✓Session takeover, path traversal into the blank master form, an event stream that leaked a signed PDF link to anyone holding the shared secret
  • ✓An SSN persisted against a tenant's own stated policy; every anonymous caller sharing one memory namespace
  • ✓An audit trail that rewrote itself when a filing was retried
  • ✓150 ms of PDF work blocking the event loop while another applicant was mid-sentence

Stated before you ask

  • —Cerebras. The account returns 402 Payment Required. It never ran, so we do not submit that track. The inference lane is provider-agnostic, so it is a config flip if credits arrive.
  • —Band memory and Band-hosted tools. ff_memory and ff_create_tools are off on the free plan. The three tiers are ours, in Postgres. Band is orchestration here, not storage.
  • —Fully emergent routing. An agent chooses who to address and does so over Band — but when it declares its own part finished, the fixed role order picks who goes next.
  • —Email delivery. The RocketRide pipeline runs, but Gmail has no credentials configured, so the code returns delivered: false rather than a green tick nobody can find in an inbox.
  • —All-generated code. Two of ten modules came from pdd --local generate; the rest are hand-written to the same prompts. The README says so, per module.
